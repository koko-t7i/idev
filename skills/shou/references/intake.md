# 阶段 0：确认调研方向

用户确认之前不搜索。

## 循环

1. 判定调研类型。
2. 分析用户请求的意图。
3. 输出复述，问 `我理解得对吗？`
4. 用户否定、补充或修改，回到第 2 步。
5. 用户确认，进入阶段 1。

同一请求确认过就不再确认。用户在阶段 1 产出之后提出的追加要求，如果改变了调研对象或范围，按新请求重新走一轮。

## 先判定类型

| 类型 | 候选粒度 | 信号词 |
|---|---|---|
| A 现成方案盘点 | 能装上就用的东西 | 有哪些、用什么、选型、竞品、对比、主流方案 |
| B 实现方案 | 机制、算法、模式 | 怎么做、什么方案、如何实现、怎么划分、架构 |

"限流有哪些开源库"是 A，"限流用什么算法"是 B。同一个主题两类都问得通时看要什么答案：要一份可选清单是 A，要一组机制和取舍是 B。

类型 B 的答案里常常包含现成组件，这不影响类型判定。"限流用 Redis 还是本地计数"问的是机制，走 B；确定要用集中式存储之后再比几个候选组件，那是 B 之后的一轮 A。

分不清时按 B 处理，并把类型列进待确认项。类型写进复述第 1 行的目标里。

## 需要从对话里提取的内容

抽不出来的标为假设，或列进待确认项。

两种类型共用：

| 项 | 说明 |
|---|---|
| 调研对象 | 要盘点什么类别的东西，或要设计什么能力 |
| 边界 | 包含什么，排除什么 |
| 用途 | 支撑什么决策，决定要比较哪些维度 |
| 已知偏好 | 用户已经表达过的倾向 |

类型 A 额外提取：

| 项 | 说明 |
|---|---|
| 比较维度 | 除热度、最近活跃、优势、缺点之外还需要哪些列 |
| 开源闭源 | 只看开源，只看商业产品，还是两者都要 |

类型 B 额外提取技术约束，它决定哪些方案根本不可选：

| 项 | 说明 |
|---|---|
| 规模量级 | 请求量、用户量、数据量的大致档位 |
| 部署形态 | 单实例、多实例、多地域 |
| 已有基础设施 | 手上有什么可用，例如 Redis、消息队列、网关、服务注册 |
| 技术栈 | 语言和框架，决定有没有成熟实现可参考 |
| 硬性要求 | 例如必须精确不能近似、必须支持自托管、有合规要求 |

约束问不到就按常见默认值假设，写进待确认那行。约束决定哪些方案可选，全靠推断时方案表会偏，所以这一项可以多问一句。

## 复述格式

上限 5 行，每行一句，不写段落，不加标题。第 3、4 行按类型取固定措辞，照写即可。

类型 A：

1. 目标：盘点什么，给什么决策用。
2. 范围：包含什么，排除什么，开源和闭源各取不取。
3. 产出：分类表格，每项一行不展开，含热度、最近活跃、优势、缺点。
4. 筛选：开源 star 大于 50，闭源需有可核实的采用度数字，只取一年内的，一年未更新按过时剔除。
5. 待确认：最多 2 条推断出来但用户没明说的假设。没有就省掉这行。

用户明确只要开源时，第 4 行可省掉闭源那半句。

类型 B：

1. 目标：要设计什么能力，给什么决策用。
2. 约束：规模量级、部署形态、手上已有的基础设施、硬性要求。
3. 产出：分组方案表，每个方案一行，含机制、适用条件、代价、典型实现，并给出默认选择。
4. 筛选：只收有生产使用记录的方案，近一年无人使用或讨论的不收。
5. 待确认：最多 2 条推断出来的约束假设。约束基本靠推断时，这行必须有。

结尾单独一行问 `我理解得对吗？`

类型 A 示例：

> 目标：盘点做 X 的主流方案，用于我们选型和定位竞品。
> 范围：开源框架和商业产品都要，排除只有演示没有在营的项目。
> 产出：按形态分组的表格，每项一行，含热度、最近活跃、优势、缺点。
> 筛选：开源 star 大于 50，闭源需有可核实的采用度数字，只取一年内的，一年未更新按过时剔除。
> 待确认：我假设你关心的是服务端方案，不含客户端 SDK。
>
> 我理解得对吗？

类型 B 示例：

> 目标：调研接口限流该怎么设计，给我们网关层选型和实现方式定方案。
> 约束：多实例部署，手上有 Redis，日请求量百万级，允许少量误差。
> 产出：按机制族分组的方案表，含机制、适用条件、代价、典型实现，并给出默认选择。
> 筛选：只收有生产使用记录的方案，近一年无人使用或讨论的不收。
> 待确认：我假设限流粒度按用户和接口两级，不含按租户配额。
>
> 我理解得对吗？

## 什么算确认

用户对当前这版复述给出明确肯定，例如"对"、"可以"、"确认"、"开始"。用户要求跳过确认或立即开始时，直接进入阶段 1。

## 反模式

- 超过 5 行，或写成分段说明。
- 一次抛出 3 条以上待确认假设。
- 追问用户已经说清楚的事。
- 在复述里夹带搜索结果或初步结论。
- 用户只补充了一个细节，就把整段复述重写。只重述被改动的行，再问一次。

## 写盘

确认后建立 `.shou/{slug}/plan.md`。开头一行记调研类型。第一节写确认后的复述全文，它是后续所有取舍的判据。第二节写检索角度清单，格式见 `landscape.md`（类型 A）或 `design.md`（类型 B）。
