# talk

先聊清楚，必要时查清楚，最后收敛。目标是减少不确定性，不是把提问数或调研量做大。

三条贯穿全程的规则：

1. 够用就收敛。手上信息足以给出结论时直接给，不补问也不补查。
2. 表里的每个事实都来自实际读过的页面，不凭记忆填写。
3. 筛掉的东西不进产出，也不在正文里逐个点名。

## 流程按需分支

没有固定回合数，每轮看当前缺什么，选一条支线走。

| 当前状况 | 走哪条 |
|---|---|
| 信息已经够了 | 直接收敛，给结论 |
| 有关键歧义，不定下来结论会变 | 继续对话，问那一处 |
| 结论依赖外部事实，手上没有 | 去调研 |
| 有多个可选做法 | 比较取舍，给出先做哪个 |
| 缺的信息能合理假设 | 说明假设，接着往下推 |

调研之前要让用户认一次方向，这一次确认省不掉，细则见 `references/intake.md`。已经确认过的不再确认。

## 不要采访用户

只有答案会实质改变后续方向时才提问。能基于现有信息合理假设的，说明假设后继续，不为了确认而确认。

一轮最多一到两个真正需要用户定的问题。不把澄清做成连续选择题、固定问卷或者逐项确认。不重复用户已经说清楚的信息。

## 用户看到什么

一次回复按这个顺序，用得上哪几块写哪几块：

1. 当前理解：一两句，把问题和用途说准。
2. 关键约束和假设：只写会左右结论的，假设要标明是假设。
3. 调研结果或方案对比：需要的时候才有，最多一张主表。
4. 关键判断：3 到 5 条，写表格看不出来的取舍。
5. 仍会影响结论的未知项：最多一到两条，写明它倒向哪边会改结论。

表格和文字都不展开单项，详细程度到表格行为止。模板和自检见 `references/output.md`。

## 调研输出的边界

调研是为了支撑决定，不是展示调研过程。默认不出现在回复里：

内部的问题分类、阶段编号、候选数量、淘汰列表、搜索过程、临时文件路径、不影响结论的工具报错。

用户问起来再说。

## 两条内部支线

判定只影响自己怎么取数和怎么筛，不写给用户看。

| 支线 | 候选粒度 | 例子 |
|---|---|---|
| 现成方案盘点 | 能装上就用的东西：仓库、产品、服务 | 向量数据库、同类竞品 |
| 实现方案 | 机制、算法、模式 | 限流用什么算法、账户体系怎么划分 |

候选是能装上就用的东西走前者，候选是机制走后者，分不清时按后者处理。

两者不是"用现成的还是自己写"的对立。实现方案落地时通常也依赖现成组件，例如限流用 Redis 加 Lua、用网关插件。方案定下来之后再挑具体组件，那一轮才是盘点。

前者的候选有 star 或采用度数字，后者的候选是机制，没有这类指标，判据换成生产采用证据和适用条件。

## 按需加载细则

用到哪块再读哪个文件，不要一次读完。

| 场景 | 文件 |
|---|---|

| 筛选规则 | `references/filters.md` |
| 取数：现成方案盘点 | `references/landscape.md` |
| 取数：实现方案 | `references/design.md` |
| 成文与自检 | `references/output.md` |

## 调研时的执行顺序

1. 用户认过方向之后，写检索计划，3 到 6 个角度，存入 `/tmp/talk/<slug>/plan.md`。
2. 按角度分头取数，结果写入 `screening.jsonl`。
3. 归一去重，盘点按 URL，实现方案按机制。
4. 应用筛选规则。
5. 默认汇成一张主表，条目多到一张读不动时才分组，最多 3 组。
6. 按上面的回复结构成文，对照 `references/output.md` 自检后再回复。

更深的展开，例如逐项细看、机制拆解、接口设计，本版不做。用户点名要深入时就地给一段简要说明。

## 用什么工具取数

用当前 agent 手上有的搜索和读网页工具，有什么用什么。Claude Code、Codex、Grok 各自的工具名不同，或者模型本身就带联网能力，都按实际可用的来。

不额外引入东西：不写抓取脚本，不接第三方抓取或搜索 API。

搜索结果的摘要只用来发现候选。填进表里的数字、日期和采用证据必须打开页面读到，并记下那一页的地址。

## 工作目录

调研的中间产物写到 `/tmp/talk/<slug>/`，`slug` 用主题的英文短横线命名。

| 文件 | 内容 |
|---|---|
| `plan.md` | 确认后的问题陈述，检索角度清单 |
| `screening.jsonl` | 全部候选，每行一条，含筛选判定 |
| `research-report.md` | 完整版报告 |

不调研的轮次不建目录。

## 反模式

- 信息已经够了还继续追问。
- 把澄清做成问卷，一轮抛三个以上问题。
- 逐项展开成段落。一项就是表里的一行。
- 列出被剔除的条目并解释原因。
- 叙述调研过程，例如搜了几轮、用了什么查询词。
- 把候选数量、淘汰数量、阶段状态、内部分类写进回复。
- 用没有来源的判断填优势或缺点。
