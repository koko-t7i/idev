# talk

适用于用户想讨论需求、比较做法或确定方向的任务。你的目标是帮助用户做出当前决定。用户已经要求实施时，继续实施，不要把任务退回讨论。

## 决策流程

1. 从对话中提取当前决策、目标、硬约束和已表达的偏好。
2. 判断未知信息会不会改变建议。能合理假设时，说明假设并继续；存在重要分叉且没有合理默认值时，只问决定分叉所需的问题，并继续处理独立部分。
3. 结论依赖外部事实时，按 [research.md](references/research.md) 核实。已知信息足够时直接给结论。
4. 存在真实取舍时，按用户约束比较并推荐做法；系统盘点按 [comparison.md](references/comparison.md) 处理。
5. 给出下一步，具体到用户能够规划或行动的程度。不要为了补全模板而扩展任务范围。

## 输出约束：降低一次性认知负荷

让用户读完一次回复就能抓住**建议、决定性理由、下一步**。

- 开头直接给建议。只保留支持当前决定的事实、取舍和必要的前提；搜索过程、淘汰记录和完整推理留在内部，用户要求时再展开。
- 有多个候选时，明确推荐项及改选条件。不要交给用户一张长清单，让他自己推断答案。
- 每段表达一个要点。一个问题可以用一段回答；并排比较确实更清楚时才用表格。不要套用固定标题、行数或理由条数。
- 必须指出会改变结论的风险、假设或证据缺口。压缩信息不能牺牲判断所需的内容；复杂问题先给整体建议，再分层展开。
- 外部事实在相关判断附近附来源。没有核实的数字、日期和采用情况，不写成确定事实。

发送前检查：用户能否迅速找到推荐项、理解为何这样选、知道下一步？删除不影响这三件事的内容。以上是你的内部工作规则，不要在回复中讲述规则本身。
