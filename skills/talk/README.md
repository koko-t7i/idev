# talk

先聊清楚，必要时查清楚，最后收敛。目标是减少不确定性，不是把提问数或调研量做大。

## 它做什么

通过对话把问题聊到清楚，必要时补充调研，最后收敛成能接着规划或实现的结论。

## 目录

```
talk/
  SKILL.md                    定位、按需分支、回复结构、规则
  references/
    intake.md                 澄清、支线判定、确认调研方向
    filters.md                筛选规则
    landscape.md              取数：现成方案盘点
    design.md                 取数：实现方案
    output.md                 回复结构、表格模板、自检
```

## 流程按需分支

没有固定回合数，每轮看当前缺什么：

| 当前状况 | 走哪条 |
|---|---|
| 信息已经够了 | 直接收敛，给结论 |
| 有关键歧义 | 继续对话，问那一处 |
| 结论依赖外部事实 | 去调研 |
| 有多个可选做法 | 比较取舍，给出先做哪个 |
| 缺的信息能合理假设 | 说明假设后推进 |

搜索之前会让你认一次方向。判断该不该问的标准只有一条：这件事不定下来，结论会不会变。

## 你会看到什么

一次回复按固定顺序，用得上哪几块写哪几块：当前理解、关键约束和假设、调研结果或方案对比、关键判断、仍会影响结论的未知项。

主表最多一张，关键判断 3 到 5 条，需要你定的问题最多两个。内部分类、阶段编号、候选数量、淘汰列表、搜索过程默认不出现，问了才说。

## 安装

复制或软链到 agent 的 skill 目录：

```bash
ln -s "$PWD/talk" ~/.claude/skills/talk
# 或 ~/.codex/skills/talk、~/.grok/skills/talk、~/.agents/skills/talk
```

## 范围

- 做：澄清、必要时调研、收敛成结论和一张表。
- 不做：逐项深入、机制拆解到接口和数据模型、写代码。
- 取数用当前 agent 手上有的搜索和读网页工具，有什么用什么。不写抓取脚本，不接第三方抓取或搜索 API。

## 筛选规则

时间基准统一为当前日期回溯 12 个月。两条内部支线的门槛不同。

现成方案盘点：

| 规则 | 说明 |
|---|---|
| 热度（开源） | star 大于 50 |
| 热度（闭源） | 至少一条带数字和来源链接的采用度证据，例如评测平台评价数、公开客户数、融资额、应用商店评分人数 |
| 过时剔除 | 最近活跃早于时效基准日的仓库、产品或文章剔除，热度高也不破例 |
| 行数 | 保留 8 到 20 行 |

闭源产品的活跃日期取 changelog、发版公告或官方博客，都没有则取最近一篇第三方报道。查不到日期的如实剔除。

实现方案：

| 规则 | 说明 |
|---|---|
| 生产采用证据 | 每个方案至少一条可核实的使用记录或权威文档，带链接。教程和面试题不算 |
| 证据时效 | 方案本身不按时间剔除，但至少要有一条时效基准日之后的证据 |
| 适用条件 | 说不清什么时候该用、什么时候不该用的方案剔除 |
| 行数 | 保留 4 到 12 行 |

门槛之外的关联性由 agent 按确认后的问题陈述判断，实现方案还要对照技术约束。

## 表格约定

盘点：列为项目、热度、最近活跃、优势、缺点。缺点必填，闭源条目在名称后标注，热度写数字加指标名且不做换算。

实现方案：列为方案、机制、适用条件、代价、典型实现。适用条件与代价必填，代价要写具体失效模式，并给出本次约束下先做哪个和换方案的触发条件。

两者都是每项一行，不展开。

## 产出

调研的轮次把中间产物和完整报告写到 `/tmp/talk/<slug>/`，回复里给路径。不调研的轮次不建目录。
