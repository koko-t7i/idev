# talk

聊清楚，查清楚，收敛。目标是消除不确定性。

## 它做什么

通过对话把问题聊清楚，缺事实就调研，最后收敛成可直接规划或实现的结论。

## 目录

```
talk/
  SKILL.md                    定位、支线选择、回复结构、规则
  references/
    intake.md                 澄清、支线判定、确认调研方向
    filters.md                筛选规则
    landscape.md              取数：现成方案盘点
    design.md                 取数：实现方案
    output.md                 回复结构、表格模板、自检
```

## 每轮选一条支线

按当前缺什么决定走法：

| 当前状况 | 走法 |
|---|---|
| 信息已够 | 收敛，给结论 |
| 有关键歧义 | 只问那一处 |
| 结论依赖外部事实 | 调研 |
| 有多个可选做法 | 比较取舍，给出先做哪个 |
| 缺的信息能合理假设 | 标明假设，继续推进 |

调研前会让你认一次方向。该不该问的标准：这件事不定，结论会不会变。会变但有合理默认值的，取默认值并标明假设；只有选错了要推翻已有成果的分叉才会问你。

## 你会看到什么

回复先给建议，再解释建议。栏目按需选用，出现的按这个顺序排：当前理解、核心问题、方案对比、建议方案、为什么这样做、落地方式、需要你决定的事项。

简单问题通常只有当前理解、建议方案、为什么这样做三块，复杂架构问题才会用满。

主表最多一张，「为什么这样做」3 到 5 条，需要你定的事项最多两条且每条自带默认取向。信息不足但有合理默认值时，按默认值给方案并标明假设。内部分类、阶段编号、候选数量、淘汰列表、搜索过程默认省略，问了才说。

## 安装

软链到共用的 skill 目录：

```bash
ln -s "$PWD/talk" ~/.agents/skills/talk
```

## 范围

- 做：澄清、必要时调研、收敛成结论和一张表。
- 超出范围：逐项深入、机制拆解到接口和数据模型、写代码。
- 取数用当前 agent 手上有的搜索和读网页工具。抓取脚本和第三方抓取、搜索 API 在范围之外。

## 筛选规则

时效基准日为当前日期回溯 12 个月。两条内部支线的门槛不同。

现成方案盘点：

| 规则 | 说明 |
|---|---|
| 热度（开源） | star 大于 50 |
| 热度（闭源） | 至少一条带数字和来源链接的采用度证据，例如评测平台评价数、公开客户数、融资额、应用商店评分人数 |
| 时效 | 最近活跃早于基准日的仓库、产品或文章剔除，热度高也照剔 |
| 行数 | 保留 8 到 20 行 |

闭源产品的活跃日期取 changelog、发版公告或官方博客，都没有则取最近一篇第三方报道。查不到日期的剔除。

实现方案：

| 规则 | 说明 |
|---|---|
| 生产采用证据 | 每个方案至少一条可核实的使用记录或权威文档，带链接。教程和面试题排除在外 |
| 证据时效 | 方案本身按机制保留，但至少要有一条基准日之后的证据 |
| 适用条件 | 说得出什么时候该用、什么时候该换 |
| 行数 | 保留 4 到 12 行 |

门槛之外的关联性由 agent 按确认后的问题陈述判断，实现方案还要对照技术约束。

## 表格约定

盘点：列为项目、热度、最近活跃、优势、缺点。缺点必填，闭源条目在名称后标注，热度写数字加指标名，各指标保持原值。

实现方案：列为方案、机制、适用条件、代价、典型实现。适用条件与代价必填，代价写具体失效模式，并给出本次约束下先做哪个和换方案的触发条件。

两者都是每项一行。

## 产出

调研的轮次把中间产物和完整报告写到 `/tmp/talk/<slug>/`，回复里给路径。只有调研的轮次才建目录。
