# 选项比较

只在存在真实取舍时比较。先确认比较对象：产品或工具、解决方法、系统中的实现位置属于不同决策，不要混在一张清单里。根据用户的目标与限制选择比较维度，不套固定模板。

## 筛选

1. 找到主要可选项，合并同一对象的别名，以及无需单独取舍的实现变体。
2. 排除不满足明确限制的选项。对剩余选项核实会改变判断的事实，方法见 [research.md](research.md)。
3. 只保留值得用户直接比较的选项。相近或明显不合适的选项可以概括；用户要求完整盘点时再扩大范围。

比较软件产品时，star、客户数或更新日期可能有用，但不是通用门槛。比较技术做法时，重点看适用条件、代价和失败方式。所有指标都应服务于本次选择。

## 呈现

先给建议，再说明决定性差异和改选条件。仅在并排比较更清楚时使用表格，列只保留本次判断需要的维度。优势、代价和适用条件要具体到当前问题，避免通用形容词。

若问题包含多个独立选择，先给整体建议，再逐项解释。不要让用户同时记住一长串不同层级的选项。用户要深入某一项时，再展开对应细节。
