# 阶段 1，类型 A：现成方案盘点

把一个已确认的调研方向变成一张分类、筛选后的表，加 3 到 7 条趋势结论。不展开单项。

前置：用户已确认调研方向，`/tmp/talk/<slug>/plan.md` 存在且含确认后的复述全文。

## 1.1 写检索计划

在 `plan.md` 第二节列出 3 到 6 个检索角度和时效基准日。角度要覆盖不同的发现渠道，开源和闭源都要覆盖到：

| 角度类型 | 说明 |
|---|---|
| 类别直查 | 该品类的通用叫法，中英文两种说法 |
| 索引与榜单 | awesome 清单、G2 或 Capterra 品类页、分析师报告、对比文章 |
| 头部项目的邻居 | 已知头部名称加 alternative、competitors 或"对比" |
| 社区讨论 | 讨论区里的选型争论，闭源方案的用户评价多在这里 |
| 商业侧 | 同类商业产品的定价页与官网，用于界定各方案的位置 |

只查开源渠道会漏掉闭源竞品，混合品类要保留商业侧和榜单这两个角度。角度数量取决于品类宽窄。

## 1.2 取数

一个角度一轮，能并行就并行。当前 agent 支持子代理时，一个角度派一个，最多 5 个同时跑；不支持就自己按顺序做完。

派子代理时，指令里要带三样东西：

1. 它负责的那一个检索角度。
2. `plan.md` 第一节的复述全文，作为关联性判断依据。
3. 返回格式，即下面的记录格式，来源链接必填，读不到的字段填 `null`。

分头取数时编排者不自己跑角度，只做计划、汇总、筛选、成文。

### 记录格式

`screening.jsonl` 每行一条：

```json
{
  "name": "owner/repo 或产品名",
  "url": "主页或仓库地址",
  "kind": "repo | product | article",
  "popularity": "8.2k star | G2 340 条评价 | 公开客户数 2000+",
  "popularity_url": "读到这个数字的页面",
  "last_active": "2026-08-27",
  "last_active_url": "读到这个日期的页面",
  "summary": "一句话它是什么",
  "verdict": "keep | drop:traction | drop:stale | drop:irrelevant"
}
```

热度字段（`popularity`）写成数字加指标名，标明这是什么指标。字段缺失填 `null`，不要猜测。文章类不需要热度字段。

### 怎么拿这两个字段

搜索结果的摘要只用来发现候选，不作为填表依据。两个字段都要打开页面读到，并记下那一页的地址：

| 类别 | 热度去哪读 | 活跃日期去哪读 |
|---|---|---|
| `repo` | 仓库首页 | 提交历史或 releases 页 |
| `product` | 评测平台品类页、官网客户页、公司融资公告、应用商店页 | changelog、release notes、官方博客，都没有则最近一篇第三方报道 |
| `article` | 不需要 | 文章本身的发布日期 |

闭源产品的两个字段常常分散在不同页面，这时 `popularity_url` 和 `last_active_url` 填各自的来源，不要合并。

### 量的上限

| 项 | 默认值 |
|---|---|
| 每个角度的候选上限 | 15 |
| 进入核实环节的候选上限 | 30 |
| 每个候选读页面的次数 | 最多 3 |

闭源产品要读的页面比仓库多，所以次数上限放到 3。候选超过上限时按关联性排序再截断，不要为了凑数扩大范围。

## 1.3 归一去重

以主页或仓库 URL 为主键合并。同一项目被多个角度命中时保留一条，`summary` 取信息量最大的那份。名称不同但指向同一仓库的按同一条处理。同一个东西的开源仓库与商业官网算同一条，按调研关注点选一种登记。

## 1.4 筛选

读 `filters.md` 的类型 A 部分，给每条候选写判定，统计评估总数、剔除数、保留数。

判定为保留的数量不在 8 到 25 之间时，按 `filters.md` 补检索或收紧，不要带着不合格的行数进入下一步。

## 1.5 分组

分成 3 到 6 组，按形态或职责划分。可用维度举例：

- 交付形态：开源框架、商业产品、插件或扩展、索引清单。
- 职责位置：编排层、能力层、基础设施层。
- 部署方式：自托管、托管服务。

不要按热门程度分组，热度已经是一列。每组至少 2 行，只有 1 行的组要么合并，要么说明它自成一类的理由。

一组内混有开源和闭源时，在项目名后标 `（闭源）`，让读者知道这一行的热度指标为什么和邻居不同。

## 1.6 成文

读 `output.md` 的类型 A 模板，按模板输出，自检通过再回复。完整版本写入 `/tmp/talk/<slug>/research-report.md`，回复用户的是同一份内容的精简呈现，结论一致。

## 交接

产出末尾给出不超过 5 个可深入的候选，说明当前版本只做到全景扫描。用户点名要深入时，告知阶段 2 未实现，可以就地给出简要说明，不要自行发明一套深入流程。
