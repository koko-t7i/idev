# 回复结构、表格模板与自检

一次回复一页读完。先给建议，再解释建议；调研和推理都为建议服务。

## 栏目

按需选用，出现的按这个顺序排：

| # | 栏目 | 出现条件 | 要求 |
|---|---|---|---|
| 1 | 当前理解 | 几乎总是 | 1 到 3 句，说准问题和用途。假设在这里标明，最多 2 条。用户刚确认过就压成半句 |
| 2 | 核心问题 | 真正的问题被表象盖住时 | 1 到 3 个，指出症状背后的成因 |
| 3 | 方案对比 | 存在多个候选时 | 最多一张主表 |
| 4 | 建议方案 | 总是 | 一个推荐做法，需要几件事配合就给组合 |
| 5 | 为什么这样做 | 总是 | 3 到 5 条，每条解释建议 |
| 6 | 落地方式 | 工程和设计类问题 | 下一步具体怎么做，目录、规则、机制能给就给 |
| 7 | 需要你决定的事项 | 只在存在不可逆分叉时 | 最多 2 条，每条给默认取向 |

轻量问题常常只有 1、4、5 三块，这是正常形态。复杂架构问题才会用到 6 和 7。凑出来的块删掉。

默认一张主表。一张读不动时才分组，最多 3 组，每组至少 2 行，每组一个不超过 20 字的二级标题。

## 表格模板：现成方案盘点

```markdown
| 项目 | 热度 | 最近活跃 | 优势 | 缺点 |
|---|---|---|---|---|
| [owner/repo](url) | 12.3k star | 2026-08-27 | 一句，不超过 25 字 | 一句，不超过 25 字 |
| [某产品](url)（闭源） | G2 340 条评价 | 2026-09-02 | 一句，不超过 25 字 | 一句，不超过 25 字 |
```

| 列 | 要求 |
|---|---|
| 项目 | 名称带链接，指向仓库或主页。闭源的在名称后标 `（闭源）` |
| 热度 | 数字加指标名。文章类填 `—` |
| 最近活跃 | `YYYY-MM-DD`，时效判定的依据 |
| 优势 | 必填。写它区别于其他项的地方 |
| 缺点 | 必填，头部方案也要填。填不出来说明核实不足，回去补 |

热度列的指标允许各行不同：开源写 star，闭源写评价数、客户数或融资额，都带指标名，保持原值。

缺点写可验证的短板：更新频率下降、依赖某家付费服务、只覆盖单一平台、文档缺失、绑定特定运行环境、许可证受限。闭源方案常见短板：无自托管、按坐席收费、接口受限、无法导出数据、路线图不公开。

## 表格模板：实现方案

```markdown
| 方案 | 机制 | 适用条件 | 代价 | 典型实现 |
|---|---|---|---|---|
| 令牌桶 | 一句话，不超过 25 字 | 一句，不超过 25 字 | 一句，不超过 25 字 | [Envoy](url) |
```

| 列 | 要求 |
|---|---|
| 方案 | 领域内通用叫法 |
| 机制 | 一句话说清它怎么工作 |
| 适用条件 | 什么条件下选它。必填 |
| 代价 | 复杂度、资源开销、已知失效模式。必填 |
| 典型实现 | 1 到 2 个带链接的实现或使用记录，链接即采用证据 |

总列数不超过 6。排除条件写进"适用条件"的反面或"代价"里。

代价写具体条目：需要额外的协调服务、集群下有时钟漂移、突发流量会放大尖峰、内存随 key 数量线性增长、热点 key 打穿单分片。"实现较复杂"这类放到任何方案上都成立的话删掉。

有多个做法时，「建议方案」直接写先做哪个、什么情况下换成另一个。约束不足以选出来时，按最常见场景取默认值并标明假设。

## 建议方案

给一个做法。多个部分能配合就写成一套组合，例如"网关层按接口做令牌桶，用户级配额放 Redis 集中计数，超限统一返回 429 并带 Retry-After"。

写到能照着动手的粒度：分层位置、键的设计、参数取值、触发机制。

## 为什么这样做

3 到 5 条，每条写成"因为 A，所以这样做"。

写这样：

> 多实例部署下本地计数器互相看不见，所以用户级配额放 Redis 集中计数。

改掉这样：

> 本地计数在多实例下不准确。

前者落到"所以这样做"，后者停在"我推出了什么"。有主表时，每条要能指回表里至少 2 行。

## 一个事实只出现一次

写进表格的，判断里省略；某条限制对多行都成立，写进分组标题下那一句。表格读得出来的信息不算判断。

## 需要你决定的事项

先判断这个缺口值不值得占一块：

| 情况 | 处理 |
|---|---|
| 存在合理默认值 | 用默认值，在「当前理解」标明假设，方案照常给完 |
| 两条路都可行，选错了改回来成本低 | 推荐一条，写清什么情况下换 |
| 选错了要推翻已做出来的东西 | 写进这一块，并给默认取向 |

最多 2 条，每条写清两边各自意味着什么，末尾给默认：

> 如果限流必须精确到零误差，得走集中式配额服务，每次请求同步扣减；允许少量误差则网关侧计数加异步同步即可。没有特别要求的话，我按允许少量误差设计。

用户已经说清目标的，直接推荐机制并往下做。用户说"接口被刷，要加限流"，就给方案，省掉"你希望限流放网关还是放服务里"。

## 一个完整例子

问题是"接口限流该怎么做"，约束是多实例部署、手上有 Redis、日请求量百万级、允许少量误差。用户已说清目标，整轮直接给方案。

````markdown
## 当前理解

多实例网关后面的接口要做限流，按用户和接口两级控制，允许少量误差。假设租户级配额暂不需要。

## 建议方案

两级分工：

1. 接口级：网关本地令牌桶，每个实例独立计数，挡住单点突发。
2. 用户级：Redis 集中计数，键为 `rl:{user}:{route}`，滑动窗口计数，Lua 脚本保证读改写原子。
3. 超限统一返回 429，带 `Retry-After` 头。

```text
参数起点
  接口级：容量 = 单实例峰值 QPS × 2，填充速率 = 单实例均值 QPS
  用户级：窗口 60s，阈值按接口分档，默认 600/min
```

## 为什么这样做

- 多实例下本地计数互相看不见，所以用户级配额放 Redis 集中计数。
- 接口级只防单点突发，允许各实例各算各的，所以放本地令牌桶，省掉一次网络往返。
- 允许少量误差，所以滑动窗口计数够用，省掉滑动窗口日志的内存开销。
- Redis 单点抖动会拖慢全部请求，所以 Redis 超时时降级为只走本地令牌桶。

## 落地方式

先在网关接本地令牌桶并上线观察一周，拿到真实峰值后再定 Redis 侧阈值，最后开用户级限流。
````

## 结尾

有报告文件时末尾一行给路径。用户点名某条要深入时，说明当前只做到清点，就地给一段简要说明。

## 自检

自己过，清单和结果省略。

| # | 条件 |
|---|---|
| 1 | 出现的栏目按表中顺序排，没有凑的块 |
| 2 | 有「建议方案」和「为什么这样做」，且建议是一个做法 |
| 3 | 「为什么这样做」3 到 5 条，每条落到"所以这样做"，有主表时能指回表里至少 2 行，且与表里信息互补 |
| 4 | 「关键判断」「仍会影响结论的未知项」只在用户点名时出现 |
| 5 | 每个信息缺口要么用了默认值并标明假设，要么确实是不可逆分叉 |
| 6 | 需要用户定的事项不超过 2 条，每条自带默认取向 |
| 7 | 主表一张，分组的话不超过 3 组，每组至少 2 行 |
| 8 | 表里每个事实都有来源页面，且那些页面实际读过 |
| 9 | 正文里每项到表格行为止 |
| 10 | 回复里的过程信息只有报告文件路径 |

调研轮次追加：

| # | 条件 |
|---|---|
| 11 | `/tmp/talk/<slug>/screening.jsonl` 存在，每条都有判定 |
| 12 | 表格行数等于判定为保留的条目数 |

盘点追加：

| # | 条件 |
|---|---|
| A1 | 保留条目数在 8 到 20 之间 |
| A2 | 每行热度带指标名 |
| A3 | 每行最近活跃晚于时效基准日；仓库类 star 大于 50；闭源产品类有带数字的采用度证据 |
| A4 | 闭源条目在项目名后有 `（闭源）` 标记 |
| A5 | 每行的优势和缺点均非空 |

实现方案追加：

| # | 条件 |
|---|---|
| B1 | 保留条目数在 4 到 12 之间 |
| B2 | 给出了先做哪个，或说明了缺哪个信息才能定 |
| B3 | 每行的适用条件和代价均非空 |
| B4 | 每行至少 1 个带链接的典型实现或使用记录 |
| B5 | 每个方案至少一条时效基准日之后的证据 |
| B6 | 代价写的是具体失效模式 |

## 输出禁令

- 「关键判断」「仍会影响结论的未知项」只在用户点名要看分析过程时出现。
- 能合理默认的信息缺口自行取默认值，回复给到结论。
- 栏目按需出现。
- 正文里每项到表格行为止。
- 调研过程省略，包括搜了几轮、用了哪些查询词、派了几个子代理。
- 内部支线名称和阶段编号省略。
- 评估数量、剔除数量、进度省略，留在 `screening.jsonl`。
- 临时目录清理之类的环境细节省略。
- 不影响结论的工具报错省略。
- 被剔除的条目及原因省略。
- 每条判断都有来源支撑。
- 各类热度指标保持原值，各自带指标名。
- 结尾省略 `Sources:` 或参考链接列表，链接已在表格里。
- `screening.jsonl` 的原始内容留在文件里。
- 有名气的方案照样写缺点和代价。
