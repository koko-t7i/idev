# 对话手法

## 推进对话的六种动作

| 动作 | 何时用 | 例子 |
|---|---|---|
| 复述 | 用户说了一大段 | "你说的是两件事：导入慢，还有失败以后不知道是哪条数据。第二件更痛。" |
| 提假设 | 有缺口但能推断 | "我假设只给内部运营用，不做权限分级。外部客户也要用的话，设计得改。" |
| 推演 | 需求还停在抽象层 | "走一遍：传了个 50MB 的文件，第 3000 行格式错了，接下来该发生什么？" |
| 指出矛盾 | 前后不一致 | "刚说要离线可用，可这功能依赖实时查询，两个只能留一个。" |
| 给取舍 | 有多条可行路 | "A 改动小，以后扩展难；B 多花两天，后面加类型不用动主干。规模会长就选 B。" |
| 量化 | 冒出形容词 | "'快'是多少？一千条数据 3 秒出结果算达标吗？" |

## 探边界怎么问

要问哪几类看需求模板那张表，这里是怎么开口：

- 量级：数据会有多少，用户会有多少，一年后长成什么样；
- 输入：最大的、空的、格式不对的、重复的，分别怎么处理；
- 出错：依赖的服务挂了、网断了、写到一半崩了怎么办；
- 并发：两个人同时改同一份数据会怎样；
- 时间：一次操作最长能跑多久，超时怎么办，历史数据留多久；
- 权限：谁能用，能不能看到别人的数据；
- 兼容：已有的数据怎么迁，老客户端还能不能用；
- 空的时候：一条数据都没有，界面和逻辑长什么样。

## 形容词怎么追成标准

| 用户说 | 追问方向 |
|---|---|
| 快 / 流畅 | 什么操作，多大数据量，几秒算达标 |
| 好用 / 友好 | 谁在用，现在卡在哪一步 |
| 稳定 / 可靠 | 能接受多久不可用，失败了怎么补 |
| 灵活 / 可扩展 | 下一个要加的是什么 |
| 智能 / 自动 | 现在哪一步靠手动，做错了怎么办 |
| 安全 | 要防的是谁，最坏会发生什么 |

## 谈不动的时候

**"你看着办"**
拟一版完整方案，把关键假设标出来让对方追认。

**用户越说越多**
新冒出来的记进待定栏，问一句：这些本期就要，还是先记着以后做？

**用户给的是解决方案**
往上追动机："你想加导出按钮，是因为现在拿数据得找开发？"

**用户反复摇摆**
给依据："这取决于将来有没有第三方接入。一年内不会的话，A 更省事。"

**只回"对""可以""嗯"**
当这轮假设全过了，记进已定栏，直接挑最薄弱的那项往下判断。

**几轮了还不知道有多少时间、用什么技术栈**
拿后果去撬："这周就要上的话，formatter 那块重构得砍掉，只做子命令。你有多少时间？"

**信息不够，判断不了**
说清楚缺的是什么，会影响哪条结论，交给用户去查。

## 反模式对照

| 不要这样 | 改成这样 |
|---|---|
| "目标用户是谁？场景是什么？数据量多大？有性能要求吗？" | 只挑最关键的一个，附上你的猜测 |
| "明白了，你想要一个文件导入功能。" | "你要的是导入，痛点在失败定位，错误报告比导入本身更关键。" |
| "这个由你决定。" | "我倾向 A，理由是……你觉得呢？" |
| 用户已说只做中文，后面又问要不要多语言 | 查账本，已定的不再确认 |
| 每轮重贴整份账本 | 只贴这轮新增的 |
